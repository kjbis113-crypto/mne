# MNÉ 주문 운영

## 현재 화면

- `/order`: 사진·기억·선호 향 접수, 직접 구매 또는 외부 구매 식별번호 확인
- `/orders`: 주문 번호/식별번호와 휴대전화로 주문 진행 조회
- `/admin`: 인증된 운영자용 주문 목록, 사진 다운로드, 제작 상태·운송장 관리, 외부 구매 식별번호 발급
- `/terms`, `/privacy`, `/refund`: 이용약관·개인정보처리방침·환불 안내 초안

상품 기준은 120ml, 배송비 포함 35,000원, 시향지 3종과 선택한 향의 본품입니다. 정책 버전은 `2026-11-06-v1`이며 주문에는 필수 항목별 동의와 선택 마케팅 동의가 각각 저장됩니다.

## Netlify 설정

다음 값은 Netlify 프로젝트 환경 변수의 Functions 범위에 설정하고 새로 배포합니다. 비밀키를 `VITE_` 변수, 소스 코드, 공개 문서에 넣지 않습니다.

| 변수 | 용도 |
| --- | --- |
| `MNE_ADMIN_TOKEN` | 운영 관리 인증키. 충분히 긴 임의의 비밀값을 사용합니다. |
| `MNE_TOSS_CLIENT_KEY` | Toss 클라이언트 키 |
| `MNE_TOSS_SECRET_KEY` | 같은 환경의 Toss 시크릿 키 |
| `MNE_PAYMENT_ENABLED` | 결제 활성화 시 `true` |
| `MNE_POLICIES_READY` | 판매자 정보와 실제 운영 정책을 최종 확정한 뒤에만 `true` |
| `MNE_MERCHANT_INFO` | 아래 판매자 공개 정보 JSON |
| `MNE_SHIPPING_ESTIMATE` | 실제로 제공할 수 있는 제작·배송 예상 일정 |
| `MNE_SUPPORT_EMAIL` | 고객 문의 이메일 |
| `MNE_ORDER_WEBHOOK_URL` | 기존 Google Apps Script 주문 수신 URL |
| `MNE_ORDER_SECRET` | Apps Script와 일치하는 주문 연동 비밀값 |

`MNE_MERCHANT_INFO`의 필드: `businessName`, `representative`, `businessNumber`, `commerceNumber`, `address`, `supportPhone`, `supportEmail`, `privacyOfficer`. 입력하지 않은 항목은 등록 예정으로 표시됩니다. 실제 값만 입력합니다.

Toss 테스트는 `test_ck_`와 `test_sk_`, 실결제는 `live_ck_`와 `live_sk_` 키를 짝지어 사용합니다. 실결제는 정책 준비 여부와 필수 판매자 정보도 확인합니다. 테스트 주문은 실제 제작 대상 목록에서 제외됩니다. 결제 금액과 승인 여부는 서버에서 검증하며, 브라우저에서 성공 화면만 열었다고 결제 완료로 처리하지 않습니다.

**정책 준비 플래그는 문서의 미정 내용을 자동으로 채우지 않습니다.** 사진·기억 보유기간과 파기 절차, 처리업체·국외이전 사항, 제작 착수 시점·취소 가능 범위·반품 비용, 상품 안전 정보 및 판매자 정보를 실제 운영 기준으로 확정하고 약관 화면을 갱신한 뒤 실결제를 켭니다. 현재 문서는 검토용 초안이며 법적 적합성 확인을 대신하지 않습니다.

## 외부 채널 구매 운영

1. 구매처에서 결제 완료와 수령인·배송지를 확인합니다.
2. `/admin`에 인증키를 입력하고 외부 구매 식별번호 발급 영역에 구매자·채널·배송 정보와 구매처 주문 번호를 입력합니다. 채널명과 주문 번호는 실제 구매처의 정보를 일관되게 사용합니다.
3. 발급된 식별번호와 접수 링크 안내를 복사해 구매자에게 직접 보냅니다. 현재 화면은 문자를 자동 발송하지 않습니다.
4. 구매자가 식별번호와 구매자 연락처를 확인해 사진·기억을 접수하면 외부 결제 주문으로 처리됩니다. 같은 주문에 추가 결제를 요청하지 않습니다.

연락처는 식별번호를 발급할 때 입력한 구매자 번호와 일치해야 합니다. 수령인 번호가 다른 경우 구매자 번호를 사용하도록 안내합니다. 식별번호를 잘못 발급했다면 해당 번호를 전달하지 말고 주문 내용을 확인합니다.

같은 채널·외부 주문 번호·구매자·배송 정보로 발급 요청을 반복하면 기존 식별번호를 반환합니다. 같은 외부 주문에 다른 정보를 입력하면 충돌 오류를 표시하므로 임의로 주문 번호를 바꾸어 재발급하지 않습니다. 화면을 닫았거나 응답을 받지 못했다면 발급 내역에서 기존 번호를 확인합니다. 발급 내역에는 접수 대기·접수 완료가 구분되며, 발급만 한 번호는 제작 주문이 아닙니다. 외부 채널의 결제·환불 상태를 자동 조회하는 연동은 없으므로 발급과 제작 전에 구매처에서 확인합니다.

## 결제 확인과 복구

관리자 주문 목록에는 실환경의 직접 주문이 결제 대기·결제 확인 중·결제 완료·결제 취소·결제 확인 필요 상태로 표시됩니다. 결제가 불확실하거나 취소된 주문은 제작 보류로 표시하며 제작 상태 변경·사진 다운로드·시트 접수 전송을 막습니다. 목록의 새로고침은 저장된 주문 기록만 읽습니다.

승인 응답을 받지 못했거나 고객이 결제 후 브라우저를 닫았다면 해당 주문 상세에서 **결제 상태 다시 확인**을 누릅니다. 이 작업은 Toss의 주문 결제 내역을 조회해 저장된 상태를 갱신할 뿐 새 결제나 중복 승인을 요청하지 않습니다. 결제 완료로 확인된 경우에만 제작을 시작합니다. 부분 취소, 금액 불일치 또는 확인 실패는 운영자 확인 대상으로 남습니다. 확인이 끝나지 않은 상태에서 새 주문이나 재결제를 안내하지 말고 Toss 대시보드의 동일 주문 번호를 대조합니다.

직접 주문의 제작 상태를 저장할 때도 결제 서비스의 승인 상태를 다시 확인합니다. 조회 실패·취소·부분 취소가 있으면 상태 변경을 거절합니다. 결제 서비스에서 취소·환불을 진행한 후에는 관리 화면에서 결제 상태를 다시 확인합니다. 현재 결제 취소 웹훅이나 주기적 자동 대조 작업은 없으므로 결제 서비스에서 발생한 변경이 즉시 자동 반영되지는 않습니다. 조회 장애가 해소되면 같은 주문의 결제 상태를 다시 확인합니다.

## 제작과 문의 대응

진행 상태는 접수 → 분석완료 → 제작중 → 시향지발송 → 선택완료 → 본품발송 → 완료입니다. 실제 진행이 끝난 단계만 저장합니다. 택배사와 운송장 번호를 함께 입력하면 고객의 주문 조회에도 표시됩니다.

사진은 관리자 인증을 거친 요청으로만 다운로드됩니다. 인증키는 관리 화면의 메모리에만 보관되며 새로고침·로그아웃 시 사라집니다. 공용 컴퓨터에서는 작업 후 로그아웃하고 다운로드한 고객 파일도 실제 보유 정책에 맞춰 관리합니다.

주문 원본과 사진은 비공개 Netlify Blobs에 보관되며 Google Sheets는 **결제가 확인된 최초 접수 시점의 운영용 연동본**입니다. 이후 결제 취소, 제작 진행 및 운송장 변경은 시트에 자동 갱신하지 않습니다. 최신 정보의 기준은 관리 화면과 결제 서비스입니다. 시트 전송이 실패해도 주문을 새로 만들거나 재결제하지 않습니다. 관리자 화면의 최초 접수 전송 상태를 확인하고 연결을 복구한 후 다시 시도합니다. 이미 전송 완료된 주문을 다시 시도해도 새 행을 만들거나 최신 상태를 덮어쓰지 않습니다.

기존 Apps Script의 주문 번호 형식을 유지하기 위해 시트 주문 번호 열에는 실제 주문 번호에서 만든 고정 `MNE-UUID` 별칭이 사용됩니다. 고객이 받는 실제 주문 번호는 `MNE-D-…` 또는 `MNE-X-…` 형식이며, 시트 **기억 설명의 맨 위**에 실제 번호·결제·배송 정보와 함께 기록됩니다. 고객 문의나 관리 화면 조회에는 실제 주문 번호를 사용합니다.

사진과 기억은 결제 전에 주문 초안과 함께 저장됩니다. 미결제 초안·사진의 만료 및 자동 삭제 작업은 아직 없으며, 현재 관리 화면에는 실주문 삭제 기능도 없습니다. 실판매 전 보유기간과 삭제 절차를 확정하고, 초안 및 완료 주문·사진·외부 코드 기록·시트 연동본에 적용할 삭제/보관 작업을 별도로 마련해야 합니다.

현재 문자 발송과 결제 취소/환불 자동화는 제공하지 않습니다. 고객 안내는 확인된 연락처로 직접 진행하고, 결제 취소는 해당 결제 서비스 또는 외부 구매처의 실제 절차를 이용합니다.

## 판매 개시 전 확인

테스트 키로 주문 입력 → 결제 → 승인 확인 → 주문 조회까지 확인하고, 외부 결제는 시험용 코드로 전화번호 일치·중복 접수 방지를 확인합니다. 실제 결제 키 전환은 판매자 정보·정책·Toss 가맹 및 상품 준비가 모두 완료된 뒤 진행합니다. 비밀키나 고객의 사진·주소를 공개 테스트 자료에 포함하지 않습니다.
